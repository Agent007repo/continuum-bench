# Method

We begin with a device-only pilot, then freeze model revisions, task sampling and analysis. The proposed local baseline measures the M1 Max natively. An edge container represents a constrained emulation on the same host, not independent edge hardware. Cloud energy will require source-backed uncertainty bands and cannot be mixed with local measurements.

The current integrator uses piecewise-linear power interpolation clipped to a request window. It requires bracketing samples and rejects excessive gaps, negative physical power and negative baseline-subtracted energy. Rejected runs must still retain their raw samples and exclusion reasons. This software function is tested; a macOS powermetrics parser and clock-alignment adapter are not implemented yet.

Routing currently implements device-small, device-large, cloud, static and constraint-aware selection. These are prototype policies, not the final requested set of baselines, cascade and learned router. Decisions use prior validation estimates. Held-out quality must not be used as an oracle feature. A quality-score ordering is not proof of parameter-size ordering, so the baseline names are provisional until a model inventory defines sizes.

We bootstrap item clusters so repeated runs of an item are not treated as independent texts. The initial helper provides a median interval, not the complete paired-effect and multiplicity analysis. Confidence signals require separate calibration. No exploratory pilot observations may enter the confirmatory set.
