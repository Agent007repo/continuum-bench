# ContinuumBench Mac protocol v1 (17 October 2026)

Identity: `ContinuumBench/mac/2026-10-17/v1`. Machine-readable version: [`configs/2026-10-17-mac-v1.json`](../../configs/2026-10-17-mac-v1.json). Committed before any Mac measurement. The 13 October draft preregistration is unchanged; this dated appendix defines the executed design. RQ3 thresholds X and Y are chosen from the Mac pilot and recorded in v1.1 before confirmatory data are collected.

## Why the Mac

A GitHub-runner design was drafted earlier the same day (`configs/2026-10-17-cloud-v1.json`) and never run. A probe showed that hosted runners have 2 vCPUs and no readable energy counters, so energy could only have been estimated. The Mac gives measured component power through `powermetrics`, a GPU through Metal, and enough memory for 7B models. The probe is reported only as a footnote.

## Design

| Element | Choice |
|---|---|
| Host | MacBook Pro 16-inch, Apple M1 Max, 64 GB, plugged in, Low Power Mode off |
| Device tier | Metal, all layers offloaded, 8 threads. Energy measured |
| Edge tier | CPU only, 4 threads, emulated small server on the same Mac. Energy measured on the Mac, tier emulated |
| Cloud tier | Characterised from documentation for the sovereignty scorecard. Not executed |
| Configurations | Qwen2.5 0.5B Q4/Q8, 1.5B Q4/Q8, 7B Q4 (owner GGUFs); Mistral-7B-Instruct-v0.3 Q4 (third-party GGUF). Edge tier: 0.5B Q4, 0.5B Q8, 1.5B Q4 |
| Items | `data/items/items-v1.jsonl`: 15 pilot and 150 confirmatory items per domain (healthcare, digital industries, general control). Automotive has no verified dataset and is a stated gap |
| Scoring | One forward pass; label with the highest first-token probability mass in the top 20 tokens; accuracy against the dataset label |
| Timing | Per-item wall and CPU time, epoch start and end. Confirmatory cells replay 10 items: 3 warm-up passes, 5 measured |
| Energy | powermetrics CPU, GPU and ANE power at 200 ms. 60 s idle baseline. Per cell, (mean power in the main-pass window minus idle) times window length, divided by items |
| Exclusions | Cells with vm_stat page-outs during the run are excluded from latency and energy. Thermal state logged |
| Splits | train 50, validation 20, test 30 percent per domain, seed 20261017 |
| H3 | Best non-oracle routing policy cuts mean energy per request by at least X percent versus always-qwen7b-q4 (device) with at most Y points accuracy loss, on the test split |

## Limits stated in advance

One machine. Component power only (no wall-plug meter, no display or memory rails). The edge tier is an emulation on the same chip. Energy is apportioned evenly across requests in a cell. Qwen 7B Q8 and Mistral Q8 fit in memory but are left out to keep total Mac compute under one hour.
